# Code structure

Stateless secure bootloader for the SeedSigner ESP32-P4. The loader reads a
Specter-signed MicroPython firmware bundle from the SD card, verifies it, and
executes it from PSRAM — then forgets everything (no state survives the jump).

Boot chain overview:

```
eFuse-secured Secure Boot V2
    └─ 2nd-stage bootloader → secure-boots seedsigner_secure_loader.bin
        └─ main.c (orchestrator)
            ├─ storage.c     mount SDMMC, read bundle, unmount (TOCTOU-safe)
            ├─ main.c        2.5  Specter section: header, platform, version,
            │                     hash, secp256k1 multisig verification
            │                     + anti-phishing proof
            ├─ esp_image.c   parse raw ESP32 image → image_plan_t
            └─ jump.c        JMP zone: MMU programming, SRAM copies, jump
                └─ payload (MicroPython firmware, runs from PSRAM)
```

## Repo layout

| Path | Contents |
|---|---|
| `main/main.c` | Orchestrator: load, verify, plan, commit, jump (no hardware code). |
| `main/storage.c/.h` | SDMMC mount + firmware bundle read into PSRAM. |
| `main/esp_image.c/.h` | ESP32 image header/segment parsing → `image_plan_t`. |
| `main/jump.c/.h` | JMP zone: ROM-safe UART, WDT/IRQ teardown, cache eviction/drain, MMU programming, SRAM copies, entry jump. RTC-RAM hand-off (`safe_*`). |
| `main/anti_phish.c/.h` | Anti-phishing proof flash provisioning + verification. |
| `main/bip39_wordlist.c` | 2048-word BIP-39 list (anti-phish vocab). |
| `main/loader_config.h` | Shared limits: `MAX_FIRMWARE_SIZE`, `MAX_SEGMENT_COUNT`, `MAX_MMU_MAPPINGS`, `MAX_DIRECT_COPIES`. |
| `main/ld/loader_high.ld` | Relocates the loader footprint to 0x4FF40000+, clear of the payload region (MEMORY redefinition, linked after esp_system). |
| `keys/` | Vendor signing keys. `keys/test/` = dev keys, `keys/production/` = release keys. `VENDOR_KEYS_PROFILE` selects the build. |
| `components/specter_crypto/` | Specter secure-app-loader component: `bl_section` (bundle format), `bl_signature` (secp256k1 multisig), secp256k1 tree. |
| `tools/` | `generate_vendor_key.py`, `generate_signed_payload.py`, `package_firmware.py`. |
| `pytest_seedsigner_bootloader_p4_stateless_os.py` | Integration test, drives the full boot over serial (`test.sh`). |

## Data flow

1. `storage.c:load_firmware_from_sd()` mounts `/sdcard`, reads
   `seedsigner_esp32p4.bin` into PSRAM, unmounts. Everything after runs against
   the PSRAM-resident copy only (TOCTOU-safe).
2. `main.c` validates the Specter `bl_section_t` header, platform attribute and
   firmware version, hashes the main section, and verifies the secp256k1
   multisig against `pubkeys_boot` (from `keys/<profile>/vendor_keys.c`).
3. `main.c` provisions/verifies the anti-phishing proof (flash-backed).
4. `esp_image.c:esp_image_plan()` parses the embedded ESP32 image:
   - MMU-mapped segments (vaddr in 0x48000000-0x4C000000) are staged into a
     fresh PSRAM `fake_flash` buffer and recorded as `mmu_mapping_t` entries;
   - internal-SRAM segments are recorded as `pending_copy_t` direct copies.
5. `main.c` commits the plan into RTC RAM (`safe_*` in `jump.c`) — it survives
   the software reset, but not a power cycle — then enters
   `do_mmu_mapping_and_jump_trampoline()`.
6. `jump.c` disables WDTs/interrupts/cache, executes the direct copies and MMU
   programming with the cache off, drains the D-cache into SRAM/PSRAM, and
   jumps to the payload entry point.

## Why things live where they do

- **Jump zone is isolated in `jump.c`** because every line there runs with the
  L1 cache disabled and on a dedicated stack. It is deliberately ROM-safe
  (stack-only strings, raw register writes) and has no dependency on the rest
  of the loader.
- **`loader_high.ld`** is a component-level linker script: a later `MEMORY`
  redefinition of `sram_low`/`sram_high` that overrides esp_system's layout
  (hence the "redeclaration of memory region" link warning — expected).
- **RTC RAM (`safe_*`)** is the only state passed from the cached world to the
  cache-off world, which is why it lives in `jump.c` next to the consumer.
- **Keys are a build-time profile** (`keys/<profile>/vendor_keys.c`), mirroring
  `cryptoadvance/specter-bootloader`. Test keys ship in-repo; production keys
  are a placeholder until generated by `tools/generate_vendor_key.py`.
